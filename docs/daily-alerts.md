# 정기 알림 운영

등록 일정: 한국시간 월–금 08:00 (UTC 일–목 23:00), cron `0 23 * * 0-4`.
GitHub Actions 예약 실행은 지연되거나 건너뛰어질 수 있어 정시 도착을 보장하지 않습니다.
일정 파일 등록 여부와 실제 최초 예약 실행 성공 여부는 별도로 확인합니다.

## 수집/비교
- 당일부터 최대 7일을 역순 조회하여 운용사에서 실제 날짜를 검증한 최신 파일만 사용
- 요청 날짜, 실제 공시 날짜, 수집 시각을 구분하며 오래된 파일을 오늘 공시로 바꾸지 않음
- 새 공시가 확인됐지만 주식 수량이 그대로면 펀드별로 ‘변동 없음’ 확인 알림 1건 발송. 휴일 등으로 새 공시 없이 직전 공시가 다시 확인된 날도 ‘새 공시 없음’ 확인 알림 1건 발송하며, ‘변동 없음’이라고 표현하지 않음
- 수집/검증 실패는 오류 상태이며 ‘변화 없음’이 아님. 실패 자체는 확인 알림으로 발송하지 않음
- 최초 실행에서 확보한 자료는 기준선만 저장하고 과거 변화를 신규 알림으로 보내지 않음
- 이후 실제 확보 날짜 사이의 정확한 주식 수량 변화만 알림. 모든 미세변화와 신규/편출 보존
- 보유 종목 과반이 같은 비율로 바뀐 날(KOACT의 CU당 일괄 조정)은 그 비율의 반올림 오차(공시 자릿수 1.5단위) 안에 드는 종목을 ‘➖ N종목 일괄 ±x% (비례 조정)’ 한 줄로 묶고, 비율에서 벗어난 종목·신규·편출만 개별 표시. 공통 비율이 1이면(TIME) 묶지 않음
- CU당 공시 수량이며 실제 체결 매매라고 단정하지 않음. 현금/파생상품은 주식 비교에서 제외
- 매번 공식 상품 페이지/API로 CU와 상품 정체 확인. 승인된 TIME20,000/KOACT50,000과 다르거나 조회 실패면 비교 보류
- 날짜 없는 현재 CU 페이지는 오늘 공시만 검증. 과거 공시는 해당 날짜에 이미 저장된 검증 근거가 있어야 하며 현재 페이지로 소급 인증하지 않음
- 첫 실행이 휴일이고 과거 공시의 CU 근거가 아직 없다면 원본/오류만 보존하고, 다음 검증 가능한 새 공시를 첫 기준선으로 삼음
- 동일 날짜 수량 수정은 자동 새 일일 알림으로 보내지 않고 검토 대기

## 저장과 중복 방지
- 같은 저장소 runtime 브랜치의 runtime/ 아래에 공시 원본, CU 근거, 날짜별 이력과 전송 원장을 영구 커밋
- GitHub workflow의 임시 GITHUB_TOKEN에 contents:write 필요. 새 개인 토큰은 만들지 않음
- 코드상 runtime/ 파일 쓰기만 허용하지만 GitHub 권한 자체는 저장소 contents 쓰기 범위이므로 신뢰할 코드만 실행
- 파일 SHA 기반 비교·교체와 조회 검증으로 영구 저장 성공 후에만 발송
- 확인 알림도 스냅샷이 영구 저장된 뒤에만 발송. 새 공시가 기준선으로 저장되므로 이후 실행에서 같은 ‘변동 없음’이 다시 생성되지 않고, 같은 날 재실행은 직전 실행 기록(runtime/latest-run.json)의 발송 기록으로 중복을 막음
- sending 상태를 먼저 저장. 전송 응답/원장 저장이 불확실하면 다음 실행에서 uncertain으로 격리
- 불확실/거절 알림을 자동 재전송하지 않고 해당 ETF 후속 알림도 검토까지 보류
- 새 수량 변화가 확인된 ETF의 대기 알림만 처리하며 다른 ETF의 오래된 대기열을 끌어와 발송하지 않음
- 남은 대기 알림도 운영 검토 필요 상태로 표시
- 서로 다른 ETF는 독립적으로 처리. 한 실행 최대 8개 메시지 조각, 수신자당 간격 1.2초
- 동일 수신자·기간·수량 상태·CU 조합은 중복 생성하지 않음
- 실행 중단시 원장이 남아 자동 재실행의 중복 발송을 방지. GitHub 동시 실행도 직렬화
- 상태 파일은 32MiB 안전 한도. 한도/손상/권한 오류는 중단하며 묵시적으로 초기화하지 않음

## 권한/실행 경계
- 봇은 @daniel45_etf_bot과 저장된 개인 chat ID만 허용. 매 예약 실행 getMe/getChat 검증
- 토큰과 chat ID는 기존 GitHub Secrets에서 읽으며 로그·코드·원장에 원문 저장하지 않음
- 수신자 지문과 Telegram message_id만 원장에 기록. 원본은 ETF의 공개 운용사 파일
- workflow_dispatch는 언제나 발송/저장 없는 수동 검증. 예약 이벤트만 승인된 알림 가능
- 추가 연결 테스트 발송은 하지 않음. 기존 웹사이트와 이 GitHub 이력은 자동 연동하지 않음

## 확인해야 할 운영 결과
원격 저장 권한, 예약 runner의 CU 소스 접근, 최초 기준선 저장은 첫 예약 실행에서 확인해야 합니다.
실패 원장은 runtime/runs/와 runtime/state.json에서 확인합니다. 실패 알림을 Telegram에 추가 발송하지 않습니다.
별도 중복 스케줄은 만들지 않습니다.
